# 单机战斗 Demo 架构草案

当前源码包含可启动的 PGRCombat 模块和项目级 Puerts 脚本宿主。每个 GameInstance 管理一个 QuickJS 环境，启动脚本已通过 UE 反射调用 C++。以下战斗组件仍为设计方案。两周建议范围为一个指定角色、一套原创或授权动作、一个能反击的敌人、一间可重开的训练场。

## 一次输入如何到达画面

| 环节 | 职责 | 首个可检验的接口 |
|---|---|---|
| Enhanced Input → 角色命令缓冲 | 记录按下、释放、顺序和单调时钟。将动作、闪避、消球意图交给状态仲裁 | 同一帧收到攻击和闪避时，测试能解释哪条生效及原因 |
| Ability / 状态仲裁 | 决定能否起手、衔接、取消、打断、扣费及结束。数据定义前摇、命中窗口、取消目标与优先级 | 以一段普通攻击和一个闪避为样例，重放输入得到同一状态序列 |
| Motion / 动画 | Montage 段、角色朝向、位移与通知。每次动作有实例标识。中断时关闭该实例的窗口，处理根运动与角色碰撞 | 中断后的旧通知不能再次造成伤害或覆写新动作 |
| 命中与受击 | 攻击方在有效时间内扫掠，防守方检查可受击状态，同一动作实例按目标去重。多段攻击显式定义段号 | 木桩边缘命中、无敌中过滤、同段去重与下一段重击均可重放 |
| 信号球 / 技能数据 | 独立维护有序球列表。先注入固定球序，再根据用户选中位置和策略决议消耗，成功受理后提交消耗并发出表现事件 | 覆盖相邻同色、被异色隔开、超过三个、空位、技能遭拒。规则由实测填写 |
| 超算、命中停顿与时钟 | 显式划分真实输入时间、角色动作时间、敌方动作时间和 HUD 时间。集中维护减速来源、到期与嵌套恢复 | 中途击败敌人、角色受击、重新开始时回到预期速度，不重复恢复 |
| AI、镜头与 HUD | 敌人先实现可重复的预警→攻击→恢复。镜头与 UI 订阅锁定、资源变更、命中等事件 | 相同敌方攻击可反复测试。相机、UI 动画或帧率变化不改变规则结果 |

## Ability 框架候选

| 方案 | 两周内的收益 | 实际成本 / 风险 | 何时值得选 |
|---|---|---|---|
| UE Gameplay Ability System（GAS） | Tags、Ability 生命周期、属性与效果、阻止与取消关系有现成表达 | 需要初始化 ASC、处理 AbilityTask 与 Montage 中断、一致地管理时间窗。单机原型很少利用复制和预测能力 | 角色参考要求多组可叠加状态、效果免疫或多条技能共享授予/取消逻辑，且最小样例能稳定回放 |
| 轻量 C++ 组件 + 数据资产 | 一个角色可直接追踪命令、当前动作实例、阶段、球序和时钟，便于对照录像与做小测试 | 取消仲裁、清理、去重和可观测性都需自行维护，随角色数增长会增加配置与维护成本 | 一名角色的普通攻击、闪避、三色技能和单敌交互即可满足验收 |
| 蓝图状态机 + Montage | 最快检查动作衔接、镜头与美术表现，编辑器迭代成本低 | 分散在图表与通知中的窗口难以批量验证。动画中断可能留下判定 | 可用于手感对照实验。长生命周期规则归到一处，通过共同的行为用例验证 |

**选型关口。** 角色确定后，以“普攻起手 → 窗口内闪避取消 → 敌方同帧攻击 → 退出无敌 → 恢复输入”为同一用例。记录行为日志、测试可写性、状态清理复杂度与制作第二招所需改动。先试与范围最匹配的候选，有实际缺口再试另一个。选择和依据写入 decisions.md。此次只确认 GAS 引擎插件可用性，尚未在项目中启用或验证 GAS。

## 两周实施顺序（建议，尚未排期验收）

| 工作日段 | 可交付片段 | 进入下一段的标准 |
|---|---|---|
| 第 1–2 天 | 选角色、动作来源与许可。建立训练场、输入、镜头、移动、一个木桩。确定上述选型 | 从干净克隆可进场，每条输入与当前状态能被观察 |
| 第 3–5 天 | 普攻连段、缓冲与取消、闪避。原创或授权骨架重定向、Montage、位移 | 两种帧率下复跑固定输入。中断、重复输入和受击后资源与状态正确收尾 |
| 第 6–8 天 | 信号球队列、对应技能、敌人预警与受击、精准闪避及超算 | 固定球列和敌方动作能重现正负对照。记录未与原作标定的参数 |
| 第 9–11 天 | 镜头、HUD、命中停顿、音画反馈。调节敌我动作速度 | 并排对照授权录像、逐项记录时机偏差与用户手感反馈 |
| 第 12–14 天 | 打包 Win64、干净机启动、回归、用户体验验收 | 可重复开战/失败/重置，分发包只含许可明确的资产，记录已知差异 |

无合适授权动作时先用原创占位资产验证规则，角色表现与相似度保持待验收。游戏包启动、帧率与操控感需要分别验收。

## AI 的执行范围与验收依赖

本轮已演示 AI 可以独立创建 C++ 模块、调用 UBT、定位输入配置警告、复测引擎地图启动并维护研究工具和版本记录。寒假可将输入、状态、队列、HUD 数据流、简化 AI 与回归用例交给 AI 按切片实现，每一阶段用编译、可重复命令和可观察的行为轨迹验收。

蓝图与 Montage 编辑、骨骼重定向、Cook 打包仍缺端到端证据。首个制作任务应拿一段原创或授权动作走完“导入 → 重定向 → Montage → 在包内触发”，记录能由命令行或编辑器工具自动完成的节点。遇到工具缺口再由用户协助具体操作。角色选择、提供或确认许可、关键规则取舍、最终手感由用户负责。完成时间取决于参考素材和该制作链是否在前两天打通。
