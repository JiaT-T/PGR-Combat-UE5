# 下一阶段的行为测量与回归用例

**优先请求的参考**是一名目标角色、该角色的形态与技能说明，以及用户手动操作录得的一段训练场原始视频。最好包含同一敌方招式的命中、普通闪避和触发超算三种结果，并有一组固定或清晰可辨的球列。未选择角色前，先保留问题与实验，避免把其他角色的特例当通则。

| 手段 | 能回答 | 主要限制 |
|---|---|---|
| 静态明文清单、标准索引与对象元数据 | 当前安装包有哪些类型、哪些组件或命名线索可以有针对性地追查 | 关联名称不能证明规则被使用。不能由动画长度推出取消窗、无敌窗，也不能由碰撞组件推出战斗判定方式 |
| 已获许可的逐帧录像 | 比较动作起手、第一次可见伤害、转入下一动作、队列变化、UI 提示、镜头变化与敌我运动节奏 | 视频帧是观察单位。没有同步输入就不能测输入时刻。掉帧、插帧、录屏延迟、命中停顿与剪辑影响结论 |
| 用户手动控制的对照测试 | 改变一个条件，检验闪避方向、消球选择、延迟输入、受击或未受击是否改变结果 | 无法直接读出内部状态、碰撞几何、逻辑 tick 或服务器判定。每次改变角色、帧率、敌方招式均需记录 |

## 建议顺序

1. **固定样本与对时。** 用户提供或确认允许分析与保存测量结果的素材。原片保存在仓库外。登记包版本、角色/形态、关卡与敌人、设备/游戏帧率、录像时间基、控制方式、是否显示同步输入。检查原片 PTS、重复帧与跳帧。没有输入画面的样本可先做视觉对齐。
2. **先测连段与闪避。** 在同距离下录制普攻单击、连续点击、延迟下一击、不同前后摇阶段尝试闪避，并录制不输入的完整动作作参照。用可见姿态/特效或同步输入作零点，标记首次衔接、首次命中、取消成功与失败。空挥与命中分开测，避免把命中停顿算入招式本体。
3. **再测信号球。** 逐次登记输入前的完整可见球列、点击位置、消失的球、重排、技能变体与新球出现时机。分别测单球、相邻两球、相邻三球、同色被隔开、超过三球及边界位置。每个观测先记结果，再归纳能解释正例和反例的规则。
4. **同一敌方招式做精准闪避与超算。** 固定敌人与起始位置，重复改变闪避相对时机。分别记录掉血、受击动画、超算提示、敌方位移、玩家动作和 HUD。触发/未触发都保留，比较玩家、敌人和 UI 三条时间线。避免从单一慢动作画面直接指定全局时间倍率。
5. **最后校准判定、AI 与表现。** 固定方向/站位，记录攻击落空与命中边界、重复命中、敌方打断与位移。改变距离观察敌人转向、选招与恢复。固定镜头输入对照锁定、距离、画面震动和 HUD 反馈。视觉遮挡或相机透视过强时，只登记事件顺序。

## 测量记录格式

每条记录使用样本 ID、包版本、角色/敌人、试验条件、参考零点、事件、帧号和 PTS、重复次数、成功/失败次数、反例、误差来源、适用范围。保留最后一次失败与第一次成功之间的区间。输入不可见则以“可见动作起始后”陈述。固定帧率的 60 fps 素材中，一帧间隔约 16.7 ms。可变帧率直接用 PTS 差。录像只能给出观测区间，程序里的窗口仍须单独建模，并用相同用例验证。

阶段产物是一份可复核的角色行为表、一组正负对照和一个最小 UE 验收用例。此次尚无原作实机或录像数据。
