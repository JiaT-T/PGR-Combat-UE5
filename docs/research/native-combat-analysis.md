# PC 4.9.1 战斗相关代码的反编译证据

2026-11-19，在本机 Windows x64 客户端上，使用 radare2 6.2.6 和 r2ghidra 6.2.6 离线反编译了 20 个函数。18 个入口属于 GameAssembly 中 Assembly-CSharp 的原生方法指针表，2 个是 RecastDll 的具名导航导出。经代码确认的七实专属方法数为 0。此处记录可复核的结论，原始反编译文本和指令保存在个人本地研究目录。

## 为什么技能类型还对应不到函数

- 普通 Unity 类型记录保留了程序集、命名空间和类名，包括 StatusSyncFight 命名空间下的 XNpcActionFSM、XNpcAnimatorComponent、XSkillInputCheckerBase、XSkillCaster、XSkillBallComponent 和 XSkillActionComponent。记录不包含这些类的方法定义编号。安装中 615 个可解析的启动场景和内置资源脚本引用全部能回到类型，其中没有按 Fight、Skill 等关键词识别出的战斗组件实例。
- 本体 64 个 EXE/DLL 均无 CLR 目录。常规 global-metadata.dat 大小为 0。GameAssembly 的调试目录引用了 GameAssembly.pdb，安装包未附带匹配的符号文件。方法指针表仍能把一个槽位连到一段机器码，目前缺失的是从具名战斗方法到这个槽位的映射。
- 针对 GameAssembly 全文件检索了 38 个动作、角色与战斗标记，覆盖用户给出的两套普攻、红蓝黄球、Attack40–48、两套必杀、Attack99、角色 ID 和别名。UTF-8 与 UTF-16LE 检索均未命中，英文同时忽略 ASCII 大小写。对已反汇编的基本块也没有发现角色 ID 1051005 的独立整数操作数。这一结果仅覆盖所列表示方式。
- 同场 Android 日志 L02 第 1322、1357–1358、1369 行依次有进入战斗、预载闪避相关配置和战斗 UI 进入的标记。没有带源码位置的逐招日志。已读的四份明文 Lua 属于工具和序列化。带有 Supercomputing 名称的无人机小游戏状态也不能作为七实超算的归属证据。

因此红蓝球两段、黄球切形态及两套普攻、Attack40–48 的分派和取消窗，继续保留为[玩家指认、录像与动作索引证据](nanami-motion-assets.md)。要让其中一条升级为原生实现证据，优先条件是同一构建的合法符号、未受保护的标准方法映射，或能明确暴露调用者与动作身份的普通脚本。仅找到新的 Unity API 调用不足以升级其归属。
