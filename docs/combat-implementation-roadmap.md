# 单角色战斗实现路线

目标是在 Windows 单机训练场中交付一个角色的完整 Ability 系统。玩家能用普攻、闪避、超算、信号球技能、角色专属机制和大招，与一名可重复出招的敌人完整交手并重开。QTE、队友切换和联机在范围之外。动作与反馈使用原创或具有明确分发许可的素材。

当前基线是 UE 5.8.4 C++ 空工程，已验证 Win64 编译和编辑器宿主的空地图启动，尚无可操作的战斗角色。目标角色与起始形态由用户确认。以下节点按功能依赖排列，均为待完成的验收目标。[基线验证](validation.md)

## 节点 0 · 锁定参考角色与可观察规则

由用户确认目标角色、起始形态和可用参考。根据正常手动游玩的记录，整理技能清单和触发条件，覆盖普攻段数与取消、闪避与超算、球列与技能档位、专属资源、核心被动、派生、角色自身形态及大招。逐条标明已观察行为、待验证问题和 Demo 原型取舍。安装包元数据只提供查证线索，具体规则和时序以受控观察为依据。

**验收时**，能按角色和形态核对技能清单，并用同一敌招下的命中、普通闪避和触发超算样本对照事件顺序。记录包版本、匿名样本 ID、试验条件、测量方法、观察量与限制。[机制证据账本](research/mechanics.md) · [手动采样与测量](research/measurement.md)

## 节点 1 · 可操控角色与动作制作链

依赖节点 0。玩家可在测试场景移动、转向、自由转镜头、锁定或解除锁定测试目标。Enhanced Input 把输入交给角色控制。用一段获准使用的动作打通骨骼导入、动作重定向、Montage 播放与角色位移，明确根运动或程序位移与碰撞的关系。

**验收时**，从移动和锁定进入动作，分别验证自然结束和被中断。两条路径都能收回本次动作的位移控制并恢复移动与镜头操作。

## 节点 2 · Ability 骨架与框架选型

依赖节点 1。占位普攻、闪避和固定时点的敌方攻击走同一条可追踪的链路。Ability 校验起手条件，通过标签与优先级仲裁互斥和取消，在受理后的约定时点结算资源，处理执行、自然结束、取消与受击打断。结束时按动作实例关闭窗口，清理标签、计时器和动画通知，恢复输入与移动控制。

**验收时**，复跑同一用例「普攻起手 → 窗口内合法闪避取消 → 敌方同帧攻击 → 退出无敌 → 再次攻击」，能解释输入顺序、同帧胜出的状态、扣费与清理结果。轻量 C++ 组件与 UE Gameplay Ability System（GAS）共用此用例，依据可重复性、清理复杂度与增加第二招的改动量择一。选型待定，验证后记录依据与复审条件。[架构草案的候选方案](architecture.md#ability-框架候选)

## 节点 3 · 命中、伤害与受击

依赖节点 2。攻击只在有效窗口内产生判定。成功命中后结算伤害、受击反应及适用的击退或打断。无敌阻挡命中结算，霸体按技能规则抵抗打断，伤害与受击反应分别判定。以动作实例、攻击段和目标去重，多段招式能按配置分别命中。

**验收时**，能复现命中距离边界、空挥、无敌、霸体、同段重复检测、多段各自命中和中断后窗口关闭，逐项核对生命值、动作状态与事件记录。

## 节点 4 · 完整普攻、输入缓冲与方向闪避

依赖节点 3。玩家能打完所选角色的全部普攻段和已确认的衔接分支。提前输入可在有效缓冲期内接到合法下一段，过期输入被清除。按角色规则处理命中与空挥时的取消差异、各方向的闪避位移、无敌与恢复窗口，以及闪避资源的消耗和恢复。

**验收时**，能打完整连段，也能在可取消窗口内转入闪避并恢复攻击。窗口外输入、缓冲过期、无方向输入和资源不足均有可追踪结果。

## 节点 5 · 极限闪避、超算与时钟恢复

依赖节点 4。玩家可改变闪避时机，打出普通闪避或极限闪避，并在触发条件满足时进入超算。配置超算持续、冷却和影响范围，明确输入、玩家动作、敌人、适用的投射物及 HUD 各自使用的时钟。管理超算和命中停顿等减速来源的叠加与恢复。

**验收时**，对同一敌招分别复现受击、普通闪避和触发超算，核对冷却内再次尝试的结果。自然结束、受击或死亡引发的中断、训练重置后，各时钟按剩余有效状态恢复。

## 节点 6 · 信号球队列与各色完整技能

依赖节点 5。玩家可按角色规则获得、选择与消耗信号球，施放每种颜色的单消、双消、三消技能及对应效果。记录队列顺序、选择位置、实际消耗与补球规则。实际扣除哪些球与能力按哪个档位生效分别结算，超算加成根据实测或已标注的原型取舍改变相应效果。合法施放一次性提交消耗，技能拒绝时保留原队列。

**验收时**，从固定球列复跑各色各档，覆盖同色相邻、同色被隔开、超过三球、无效位置和技能遭拒。对照超算内外的消球结果，分别核对扣球、重排、实际技能档位和加成。

## 节点 7 · 专属资源、核心被动、强化与自身形态

依赖节点 6。按所选角色的已确认规则实现专属资源的获取、上限、消耗和清理，以及核心被动、强化条件和派生招式。若参考角色具有自身形态切换，为同一可控角色配置形态进入、退出、技能映射和资源继承，处理受击中断及退出时的清理。

**验收时**，能从常态通过规定招式和资源触发核心被动，施放强化或派生技能，再按该角色的规则继续战斗。检查未满足条件时的行为，以及适用形态的进入、退出和中断后的动作与资源。

## 节点 8 · 大招与完整角色循环

依赖节点 7。大招接入同一 Ability 生命周期，具备资源积累、起手条件、消耗、命中、结束及适用的取消或打断规则。打通大招与普攻、消球、核心被动及专属资源之间经确认的交互，包含适用的强化、派生和自身形态变化。

**验收时**，按技能清单触发每个可用技能与变体。能从初始状态通过普攻和消球推动角色机制，满足条件后施放大招，恢复后再次积累并重复循环。日志能追溯每次施放的条件、资源变化和退出结果。

## 节点 9 · HUD、战斗反馈与单敌训练场

依赖节点 8。玩家可在训练场反复练习完整循环。敌人可重复执行预警、攻击与恢复，玩家能重开并恢复初始站位和战斗状态。HUD 显示生命、球列、闪避与专属资源、大招可用性和超算提示。镜头、命中停顿和音画反馈依据战斗事件表现命中、受击及技能触发，结算结果可单独核对。

**验收时**，可连续完成普攻连段、闪避触发超算、消球、核心被动与大招。能在实战和重置后核对 HUD、镜头和战斗状态，使用同一敌招重复练习。

## 节点 10 · Win64 打包、回归与交接

依赖节点 9。完成 Cook 与 Win64 打包，在打包版进入训练场、使用完整角色、击败敌人、战败和重开。固定输入和敌招回归覆盖非法输入、资源不足、合法与非法取消、受击中断、低帧率、同帧输入与命中冲突、双方死亡及反复重置。

**验收时**，从干净检出能按仓库说明构建并启动打包版。轨迹可按 Ability 与动作实例追查输入、状态、命中、资源与时钟，并核对结束后的清理结果。交接能从 C++ 状态逻辑定位到蓝图、Montage 和数据资产的配置入口，查到技能覆盖与已知差异。打包运行、行为回归和人工手感验收各有结果。
